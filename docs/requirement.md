# 需求文档

## 项目定位

本项目是一个短视频 Feed 系统，用于展示从零设计和实现一个中等复杂度全栈项目的能力。系统围绕短视频发布、播放、互动、推荐式信息流、异步事件处理和实时通知展开，重点体现后端架构设计、缓存策略、消息队列、数据一致性、接口设计和工程化能力。

项目不是对已有开源项目的改名或搬运，而是基于短视频业务场景重新定义需求、设计架构并逐步实现。第一阶段优先保证最小闭环可以运行，后续再引入缓存、异步任务、分片上传和实时通知等增强能力。

## 用户角色

### 未登录访客

- 可以浏览公开的视频 Feed。
- 可以查看视频详情、作者主页和公开统计信息。
- 不能发布视频、点赞、评论、关注、发送私信或接收个人通知。

### 登录用户

- 可以维护个人资料。
- 可以上传、发布和管理自己的视频。
- 可以点赞、评论、关注其他用户。
- 可以查看关注流、个人通知和私信列表。

### 系统 Worker

- 消费业务事件并执行异步任务。
- 负责统计更新、热度计算、通知生成、Feed 时间线更新等非同步主链路任务。

## 功能模块总览

系统按业务边界拆分为以下模块：

- 账号模块：注册、登录、鉴权、用户资料和主页统计。
- 视频模块：视频上传、封面上传、发布、详情、作者作品和标签。
- 分片上传模块：大文件分片上传、状态查询、合并和断点续传。
- Feed 模块：最新流、关注流、热榜、点赞榜、话题流和游标分页。
- 互动模块：点赞、评论、关注以及相关统计。
- 通知模块：点赞、评论、关注和提及通知，支持 SSE 实时推送。
- 私信模块：用户之间发送私信和查看会话。
- 后台任务与异步处理：事件消费、重试、热度更新和通知投递。
- 工程化模块：配置、日志、健康检查、容器化、测试和 CI。

## 账号模块

### 注册

用户可以使用用户名、密码完成注册。用户名需要唯一，密码需要加密存储。注册成功后返回基础用户信息，不直接暴露密码摘要等敏感字段。

### 登录

用户可以使用用户名和密码登录。登录成功后系统签发访问令牌，后续需要鉴权的接口通过令牌识别用户身份。

### 登出

登录用户可以主动登出。后续阶段可通过 Redis 维护 Refresh Token 或 Token 黑名单，使登出在服务端生效。

### 用户资料

登录用户可以修改昵称、头像和个人简介。用户主页展示公开资料、作品数量、获赞数量、粉丝数量和关注数量。

### 鉴权要求

- 浏览公开 Feed 和视频详情不强制登录。
- 发布视频、点赞、评论、关注、私信、通知等接口必须登录。
- 用户只能修改自己的资料和管理自己的视频。

## 视频模块

### 视频上传

MVP 阶段支持普通表单上传，文件先存储在本地磁盘。上传成功后返回文件访问地址或资源标识。

### 封面上传

用户可以上传视频封面。若未上传封面，后续可扩展为服务端自动截帧生成封面。

### 视频发布

用户上传视频资源后，可以填写标题、描述和话题标签并发布。发布后视频进入公开 Feed。

### 视频详情

视频详情展示视频基础信息、作者信息、播放地址、封面、标题、描述、发布时间、点赞数、评论数和当前用户是否已点赞。

### 作者作品列表

用户主页可以查看指定作者发布的视频列表，按发布时间倒序排列。

### 标签与话题

视频可以携带多个话题标签。后续通过话题流支持按标签浏览视频。

## 分片上传模块

分片上传用于大文件和弱网络场景，MVP 阶段可暂不实现，但需要在架构和接口设计中预留。

### 初始化上传

客户端提交文件名、文件大小、文件哈希、分片大小等信息，服务端创建上传会话并返回上传任务标识。

### 上传分片

客户端按分片编号上传文件块。服务端记录每个分片的完成状态，重复上传同一分片应保持幂等。

### 查询状态

客户端可以查询上传任务当前已完成的分片列表，用于断点续传。

### 合并分片

所有分片上传完成后，客户端请求合并。服务端校验分片完整性和文件哈希，合并生成最终视频文件。

### 失败处理

上传会话需要设置过期时间。过期或失败的临时分片文件由后台任务清理。

## Feed 模块

### 最新流

按发布时间倒序展示公开视频，是 MVP 阶段的主要 Feed。

### 关注流

展示当前登录用户关注作者的视频。后续可通过 Redis 时间线或数据库查询实现，优先保证正确性，再优化性能。

### 热榜流

根据点赞数、评论数等因素计算热度分数，展示近期热门视频。

### 点赞榜

按点赞数排序展示视频，用于体现排行榜和 Redis ZSET 的使用场景。

### 话题流

按话题标签展示视频列表，支持通过标签页或搜索入口进入。

### 分页要求

Feed 使用游标分页，避免传统 offset 在数据持续新增时出现明显重复、漏数据和深分页性能问题。

## 互动模块

### 点赞

登录用户可以点赞视频，也可以取消点赞。同一用户对同一视频只能保持一个点赞状态。点赞状态需要支持幂等处理。

### 评论

登录用户可以发表评论。评论列表按时间排序展示。评论作者或视频作者可以在权限允许范围内删除评论。

### 关注

登录用户可以关注或取消关注其他用户。不能关注自己。关注关系用于用户主页统计和关注流。

### 统计

系统需要维护视频点赞数、评论数、用户粉丝数、关注数、作品数和获赞数等统计字段。MVP 阶段可以同步更新，后续通过事件异步更新并保证最终一致性。

## 通知模块

### 通知类型

- 点赞通知：用户的视频被点赞时生成。
- 评论通知：用户的视频被评论时生成。
- 关注通知：用户被其他用户关注时生成。
- 提及通知：评论内容中提及用户时生成，后续阶段实现。

### 通知列表

登录用户可以查看自己的通知列表，并标记通知为已读。

### 实时推送

后续阶段使用 SSE 推送实时通知。SSE 用于服务端到客户端的单向推送，适合通知类场景，复杂度低于 WebSocket。

## 私信模块

### 发送私信

登录用户可以向其他用户发送文本私信。MVP 阶段可暂不实现，后续作为社交能力扩展。

### 会话列表

用户可以查看最近会话列表，包括对方用户、最后一条消息和未读数量。

### 消息列表

用户可以查看某个会话的历史消息，按时间分页加载。

## 后台任务与异步处理

阶段 4 先实现 RabbitMQ 和 Worker 骨架，处理同步接口之外的事件入口：

- 点赞、取消点赞事件发布。
- 评论创建、删除事件发布。
- 关注、取消关注事件发布。
- Worker 消费互动事件并记录处理日志。
- 后续再补完整统计更新、热度更新、通知生成和失败补偿。

同步接口仍负责核心数据库写入和原有响应，MQ 发布失败不应影响主链路可用性。

后续阶段继续扩展 Worker 和消息队列，处理同步接口之外的任务：

- 点赞事件落库和统计更新。
- 评论事件落库和统计更新。
- 关注事件统计更新。
- 热度分数重算。
- Feed 时间线更新。
- 通知生成和投递。
- 过期上传会话清理。

异步处理需要具备重试机制、幂等处理和失败记录，避免消息重复消费导致统计错误。

## 非功能需求

### 性能

- Feed 列表接口应支持游标分页。
- 视频详情后续通过 Redis 缓存降低数据库压力。
- 热榜和点赞榜后续使用 Redis ZSET 支撑排序查询。

### 可用性

- 服务提供 `/healthz` 健康检查。
- 外部依赖不可用时需要有明确错误返回或降级策略。
- Worker 重启后应能继续处理未完成事件。

### 安全

- 密码必须加密存储。
- 鉴权接口必须校验登录态。
- 上传文件需要校验大小、类型和存储路径。
- 用户只能操作自己有权限的资源。

### 可维护性

- 后端按领域和基础设施分层组织代码。
- 前端按页面、业务特性、接口和状态管理拆分。
- 文档与实现同步更新，接口、数据库和面试讲解分文档维护。

### 可部署性

- 后续通过 Docker Compose 启动 MySQL、Redis、RabbitMQ、后端和前端。
- 提供 `.env.example` 说明必要配置。
- README 记录本地启动和验证流程。

## MVP 范围

第一版可运行系统聚焦最小短视频闭环：

- 用户注册、登录和 JWT 鉴权。
- 视频上传、封面上传和发布。
- 首页最新视频流。
- 视频详情页。
- 用户主页和作者作品列表。
- 本地文件存储。
- MySQL 持久化。
- 后端健康检查。
- 前端登录、注册、Feed 和发布页面。

MVP 阶段可以暂不实现 RabbitMQ、Redis 热榜、SSE、私信和分片上传，但代码结构需要为后续扩展预留边界。

## 后续扩展

后续阶段按以下顺序增强：

1. 增加点赞、评论、关注和用户主页统计。
2. 引入 Redis，实现视频详情缓存、热榜、点赞榜、限流和 Token 管理。
3. 引入 RabbitMQ 和 Worker，实现互动事件异步处理、热度更新和通知生成。
4. 实现 SSE 实时通知、私信和分片上传。
5. 完善 Docker Compose、CI、单元测试、接口测试、监控和面试讲解文档。
